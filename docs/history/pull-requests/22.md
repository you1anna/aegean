## Description

## Summary

This change is a behaviour-preserving refactor of the workflow domain. It is the first of two PRs. The second will split `resumeRun` in `src/application/engine.ts` into stages. It will stack on this branch.

`src/domain/workflow.ts` had four jobs: a SHA-256 helper, loading the policy pins, the run and event model, and the state machine. About 20 modules, adapters among them, imported the state machine only to get `digest`. `transition` was one 110-line switch.

| Module | Owns |
| --- | --- |
| `src/domain/digest.ts` | `digest` and the hash format check. |
| `src/domain/workflow-policy.ts` | Policy pins from `toolchain.json`, moved verbatim. `POLICY_IDENTITY` is unchanged. |
| `src/domain/run.ts` | `Run`, `Event`, `createRun`, `assertRunPolicy`, `STOP_REASONS`, and one owner for `STATES` and `TERMINAL_STATES`. |
| `src/domain/workflow.ts` | `transition` only: a fixed preamble and postamble, and one named handler for each event. Each handler keeps its own list of the evidence that it clears. |

- The ledger schema, `engine.ts` and the guide's `ENDED` derived their state lists from copies. They now derive them from `run.ts`.
- Importers use the owning module directly. `workflow.ts` has no re-export layer.
- `src/application/engine.ts` changes only its imports and two state-list checks.
