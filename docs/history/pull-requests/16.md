## Description

## What this lets the user do

An interrupted `scripts/dev` or bootstrap run leaves `.aegean/source-launcher` (or `.aegean/source-task`). Before this change, the next run printed only:

```
Source commands locked. Inspect .aegean/source-launcher/owner before recovery.
```

The message did not say if the owner still runs or how to recover. Now `scripts/dev` reads the recorded PID and gives one of three messages:

- **Owner no longer runs:** it says this and prints the exact command `rm -r "<repo>/.aegean/source-launcher"`.
- **Owner still runs:** it names the process and its command, and tells the user to wait. It gives no removal command.
- **No owner recorded:** it tells the user to investigate before removal.

The interrupt and terminate messages now also give the removal command. Locks are still never removed automatically, so the lock still fails closed.

Observed output for a stale lock:

```
Source commands locked by process 99999, which no longer runs. An earlier command was interrupted.
If no other Aegean source command runs (check: pgrep -fl "scripts/dev|dev-tasks"), remove the lock and run this command again:
  rm -r "~/Projects/aegean/.aegean/source-launcher"
```
