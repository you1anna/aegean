## Description

## What this lets the user do

At a terminal, `aegean` commands now show results as text for a person instead of raw JSON:
labelled fields, ✔/✖/! host checks, a run table, UTC dates, durations, and next steps with each
command on its own unbroken line. An `error` or `blocked` field comes first.

To a pipe or a file, or with `--json`, the output is the existing JSON, byte for byte.
Failures follow the same rule on standard error. Exit codes do not change.

## Changes

- `src/application/cli-output.ts`: a pure renderer with no I/O. It keeps every fact of the JSON form.
  It removes terminal control sequences, C1 controls and bidirectional overrides from results and script text.
  It limits lists to 200 items and nesting to 12 levels, with a pointer to `--json`.
  It finds JSON in installer script output (whole text, or warnings followed by one JSON line).
- `--json` works on every command except `guide`, including `--version`. It is removed before
  dispatch, because `auth`, `verifier` and `project` read subcommand words by position.
- JSON output cannot throw after a command has effects (cycles, `bigint`). Any thrown value gives an error message.
  `EPIPE` from an early-closing reader (`| head`) is ignored instead of crashing.
- `checkLevel` in `src/domain/guide.ts` is the one owner of the meaning of a host check; the guide and the CLI use it.
- The next-step text now says "reports that the full workflow is not ready" instead of a JSON field name.

Deliberate exclusion: the approval and publish prompt still shows `Exact artifact:` as JSON
(`decision-commands.ts`). It is the exact artifact that the human decision binds to.

- Table alignment counts characters, so wide (CJK or emoji) characters can misalign a column.
- Text output shows up to 200 list items; JSON has all of them.
