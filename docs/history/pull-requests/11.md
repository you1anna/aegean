## Description

## What this change lets the operator do

The operator used `aegean guide` on pilot project run `trial-03` to the specification review. The pilot notes record the run. This change corrects the faults from that session.

- **Read a specification file.** The guide printed a file, then read the status and drew the run menu below the text, so the file left the screen after 1 to 2 seconds. The guide now opens each file in the pager (`PAGER`, or `less`) and returns to the file list. The list marks each opened file and moves to the next file. If the pager cannot start, the guide prints the file and waits for an answer.
- **See that a draft is not complete.** `status --run`, the guide and the `aegean approve` prompt read the open questions and the `NOT COVERED` needs from `review-notes.md` as the file is now, and state their counts. The guide asks one more question before the approval of such a draft. No gate refuses; the human decides.
- **See the time that remains.** The guide shows the minutes that remain in the pilot authorisation for each run state. Below 15 minutes, the line is a warning.
- **Get a more exact draft.** The Scout prompt asks for exact names, fields, types and identifier formats, for a recommendation with each open question, and for Markdown structure. It tells the Scout not to move a need of the request to a later change.
- **Read long lines.** Guide text breaks at spaces. An echoed command stays on one line.

## Design

- `review-notes.md` is the one owner of the review items after the draft. `parseReviewNotes` is next to its writer in `src/domain/scout.ts`.
- The pager is behind a new `page` method of the `GuideUi` port. `src/adapters/terminal.ts` owns the process.
- The policy version did not change: context selection and the verification rules are the same.
