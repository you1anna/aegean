## Description

## Problem

At a terminal, `aegean qualify` printed lines wider than the terminal. The renderer kept each word whole. A digest, a receipt path or a comma list without spaces (`tools=[a,b,c]`) therefore ran past the edge, and the terminal wrapped it at column 0. Each qualification observation also used four rows: name, observed at, outcome and detail.

## Change

- `wrap` (`src/adapters/terminal.ts`) breaks a word after a comma only when the word is too long for the line. Other words stay whole, so a path or a digest is never cut and a copy stays complete.
- A value that does not fit beside its label starts on the next line, where it has more room. This uses the same layout that narrow columns already used.
- A list of named results with a `pass`, `fail` or `unknown` outcome shows one line for each result: a mark (✔, ✖ or ?), the name and the outcome word. The other fields follow below that line.
- An `outcome` field shows in the colour of its mark.

The JSON output does not change. The text output keeps every fact: the outcome word stays on the name line, and the tests check every string value.

## Limits

A single word with no comma that is wider than the space below its label still runs past the terminal edge. An example is the receipt path at about 80 columns. This is intentional, because cutting a path or a digest would break a copy. Use `--json` for exact values.
