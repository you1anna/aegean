## Description

## Summary

The test "routing mutations serialize and explicit recovery refuses a live owner but recovers a stopped owner" failed once during `sh scripts/bootstrap.sh`:

```
Error: Aegean routing: invalid installation lock; manual process audit required
    at withInstallationLock (scripts/routing.mjs:129)
```

Only one condition produces this message: the `pid` in `installation-lock/owner.json` is not a positive integer. The test writes that file itself. It takes the PID from the output of a child `node -e 'console.log(process.pid)'` and does not check the value. So the bad value came from the fixture, not from the lock code. The lock code correctly refused a lock file that it could not trust.

This change asserts that the PID is a positive integer before the test writes it. If the check fails, the message shows the raw child output.

## Root cause

The root cause is unknown. I could not reproduce the failure:

- The test alone, through mise: 5 of 5 runs passed.
- The full `dist/test/installation.test.js` file: 3 of 3 runs passed.
- The same `checked()` PID helper, 500 calls with 25 in parallel: 0 invalid values.

This PR does not fix the intermittent failure. It makes the failure point at its real cause the next time it occurs.
