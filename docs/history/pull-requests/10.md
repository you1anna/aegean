## Description

## Problem

`aegean cancel --run trial-02-…` failed on release `0.1.0-0c289ca0c4d2` (policy 0.5.0) because policy 0.4.0 created that run:

```
{"error":"run policy differs from installed policy; use its original release or cancel; no implicit migration", ...}
```

The domain already exempts `cancel` from the policy check (`transition()`). But `acquireRunPermit` and `ledger.owned` both call `assertOwned`, which applied the policy check to every run. So an older-policy run could not be cancelled, and the documented "cancel-only" route did not work.

## Change

- `assertOwnership` checks ownership only. `assertOwned` = ownership + installed policy (unchanged for all effect and state callers).
- Permit bookkeeping (`acquireRunPermit`, `reconcilePermitIntent`, `resumeOwned`, `releaseBuilder`, `releasePermits`) uses ownership only. Each entry point that executes effects (`resume`, `recover`, decisions, engine updates) still checks the policy first.
- New `cancelOwned`: ownership only. The change must end in `cancelled` and must keep the run identity. `aegean cancel` uses it.
- The shared terminal-release code moved, unchanged, into `applyOwnedChange`.
- A schema-1 run keeps its "policy differs" error.

## Verification

- Test first: the new ledger test failed at `acquireRunPermit` with the same error as the real run, then passed.
- The test shows that an older-policy run can reacquire its permit and be cancelled (ownership and permits released, policy kept), and that `owned`, `claimBuilder`, `assertOwned`, a non-cancel change, an identity change and a foreign host all fail.
- Current-policy cancellation goes through `cancelOwned` in the existing terminal-transition test.
