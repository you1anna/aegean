## Summary

This change is a behaviour-preserving refactor of the engine and the model context. It is the second of two PRs. The first was #22.

`resumeRun` in `src/application/engine.ts` was one function of about 370 lines. Its nine stages shared mutable state through closures. The prompt text, two copies of the PR find-or-create code and two copies of the verifier wrapper were inline in it.

| Module | Owns |
| --- | --- |
| `src/application/engine.ts` | The entry points. `resumeRun` opens a session; `advance` calls the stages in the original order, with the checks between stages where they were. |
| `src/application/run-session.ts` | `RunSession`: the latest ledger record of the run (`session.run`), and the effects that the stages share: `open`, `update`, `assertOwned`, `authorization`, `model` and the pause on a context fault. |
| `src/application/run-stages.ts` | One function for each workflow state, with the original statements. A stage gives `NEXT`, `STOP` (leave the build loop) or a result that ends the resume. The types keep each stage to its own outcomes. |
| `src/domain/prompts.ts` | The test Auditor, Builder and review Auditor prompts, byte-identical. |
| `src/domain/context.ts` | Context framing, the required-first order and the prompt record. Each had a copy elsewhere. |
| `src/domain/digest.ts` | `identity` (canonical JSON hash) moves here verbatim from `model-policy.ts`, next to `digest`. |
| `src/domain/run.ts` | `RUN_ID` replaces eight copies of the run identifier pattern. Each caller keeps its own error message. |

Other moves: `saveCandidate` goes to the candidate Git adapter, and `requireSubscriptions` goes to `runtime.ts`. No module imports `engine.ts`.

### `src/domain/context.ts`

This PR also reviews this module. Three facts had a second copy elsewhere, and the module depended on the model policy only for a hash function.

- `contextFragment` is the one owner of the `\nFILE "path"\n…\n` framing. Before, `model-context.ts` copied the template to count the framing bytes in its size check. If the two copies differed, the size check and the bounded context would disagree at the limit.
- `byContextPriority` is the one owner of the `required-first-v1` order. Both sorts use it.
- `promptRecord` is the record of a complete prompt. It moved from the engine. Its key order and scope text are unchanged.
- `context.ts` now imports `identity` from `digest.ts`, not from the model policy.
- Not changed: `toolOutputAllowance` stays. It also bounds the bytes that reach a model, and the module is 35 lines, so a split has no measured benefit.
- A trap that I kept, not fixed: manifest hashes use `identity(text)`, which is the SHA-256 of `JSON.stringify(text)`. Prompt records use `digest(text)`. The values differ. Both are recorded evidence, so the tests now pin which one each record uses.
- The Builder contract uses a different, unquoted framing (`\nFILE path\n…`). It stays in the Builder prompt, because its bytes differ from `contextFragment`.

### Kept on purpose: two differences for a follow-up

The spec-review and candidate-publication paths each had a PR find-or-create block. The shared `upsertPullRequest` keeps their two differences and names them:

1. Only candidate publication passes the abort signal to `gh pr list`.
2. Only candidate publication refuses more than one matching PR.

These look like gaps in the spec-review path. A fix changes behaviour, so it belongs in a separate PR.
